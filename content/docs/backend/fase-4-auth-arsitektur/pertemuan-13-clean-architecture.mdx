---
title: "Pertemuan 13 · Arsitektur Bersih (Clean Architecture)"
description: Separation of concerns dan dependency inversion dengan layer Domain, Repository, Service, dan Handler.
---

Saat fitur bertambah, kode yang menumpuk di handler menjadi sulit diuji dan diubah. **Clean Architecture** memisahkan tanggung jawab ke dalam layer yang terisolasi sehingga logika bisnis tidak bergantung pada framework atau database.

## Tujuan Pembelajaran

- Menerapkan Separation of Concerns.
- Menerapkan Dependency Inversion Principle.
- Membagi proyek menjadi layer: Domain, Repository, Service, Handler.
- Menyusun dependency injection sederhana.

## 1. Prinsip Utama

- **Separation of Concerns**: setiap layer hanya menangani satu tanggung jawab.
- **Dependency Inversion**: layer dalam (business logic) mendefinisikan interface; layer luar (database, HTTP) mengimplementasikannya. Arah ketergantungan selalu menuju ke dalam.

```text
        ┌──────────────────────────────┐
        │      Handler (Delivery)      │  HTTP / Gin
        └──────────────┬───────────────┘
                       │ memanggil
        ┌──────────────▼───────────────┐
        │       Service (UseCase)      │  logika bisnis
        └──────────────┬───────────────┘
                       │ bergantung pada interface
        ┌──────────────▼───────────────┐
        │      Repository (Data)       │  GORM / PostgreSQL
        └──────────────────────────────┘
```

## 2. Struktur Direktori

```text
myapp/
├── main.go
├── internal/
│   ├── domain/          # entity + interface
│   │   └── user.go
│   ├── repository/      # implementasi akses data
│   │   └── user_repository.go
│   ├── service/         # business logic
│   │   └── user_service.go
│   └── handler/         # delivery (HTTP)
│       └── user_handler.go
└── pkg/
    └── database/
        └── postgres.go
```

## 3. Domain Layer (Entities & Interfaces)

Layer ini tidak tahu apa pun soal HTTP atau database.

```go title="internal/domain/user.go"
package domain

import "context"

type User struct {
	ID    uint
	Name  string
	Email string
}

// kontrak yang harus dipenuhi repository
type UserRepository interface {
	Create(ctx context.Context, user *User) error
	FindByID(ctx context.Context, id uint) (*User, error)
	FindAll(ctx context.Context) ([]User, error)
}

var ErrUserNotFound = errorUserNotFound("user tidak ditemukan")

type errorUserNotFound string

func (e errorUserNotFound) Error() string { return string(e) }
```

## 4. Repository Layer (Data Access)

Mengimplementasikan interface dari domain memakai GORM.

```go title="internal/repository/user_repository.go"
package repository

import (
	"context"
	"errors"

	"gorm.io/gorm"

	"myapp/internal/domain"
)

type userRepository struct {
	db *gorm.DB
}

func NewUserRepository(db *gorm.DB) domain.UserRepository {
	return &userRepository{db: db}
}

func (r *userRepository) Create(ctx context.Context, user *domain.User) error {
	return r.db.WithContext(ctx).Create(user).Error
}

func (r *userRepository) FindByID(ctx context.Context, id uint) (*domain.User, error) {
	var user domain.User
	err := r.db.WithContext(ctx).First(&user, id).Error
	if errors.Is(err, gorm.ErrRecordNotFound) {
		return nil, domain.ErrUserNotFound
	}
	return &user, err
}

func (r *userRepository) FindAll(ctx context.Context) ([]domain.User, error) {
	var users []domain.User
	err := r.db.WithContext(ctx).Find(&users).Error
	return users, err
}
```

## 5. Service Layer (Business Logic)

Berisi aturan bisnis dan **tidak tahu** soal Gin.

```go title="internal/service/user_service.go"
package service

import (
	"context"

	"myapp/internal/domain"
)

type UserService interface {
	Register(ctx context.Context, name, email string) (*domain.User, error)
	GetByID(ctx context.Context, id uint) (*domain.User, error)
	List(ctx context.Context) ([]domain.User, error)
}

type userService struct {
	repo domain.UserRepository
}

func NewUserService(repo domain.UserRepository) UserService {
	return &userService{repo: repo}
}

func (s *userService) Register(ctx context.Context, name, email string) (*domain.User, error) {
	user := &domain.User{Name: name, Email: email}
	if err := s.repo.Create(ctx, user); err != nil {
		return nil, err
	}
	return user, nil
}

func (s *userService) GetByID(ctx context.Context, id uint) (*domain.User, error) {
	return s.repo.FindByID(ctx, id)
}

func (s *userService) List(ctx context.Context) ([]domain.User, error) {
	return s.repo.FindAll(ctx)
}
```

## 6. Handler Layer (Delivery)

Hanya menerjemahkan HTTP ke pemanggilan service.

```go title="internal/handler/user_handler.go"
package handler

import (
	"net/http"

	"github.com/gin-gonic/gin"

	"myapp/internal/service"
)

type UserHandler struct {
	svc service.UserService
}

func NewUserHandler(svc service.UserService) *UserHandler {
	return &UserHandler{svc: svc}
}

func (h *UserHandler) GetByID(c *gin.Context) {
	id := c.Param("id")

	var uid uint
	if _, err := fmt.Sscanf(id, "%d", &uid); err != nil {
		c.JSON(http.StatusBadRequest, gin.H{"error": "id tidak valid"})
		return
	}

	user, err := h.svc.GetByID(c.Request.Context(), uid)
	if err != nil {
		c.JSON(http.StatusNotFound, gin.H{"error": err.Error()})
		return
	}

	c.JSON(http.StatusOK, gin.H{"data": user})
}
```

## 7. Wiring di main.go

```go title="main.go"
func main() {
	LoadEnv()
	if err := ConnectDB(); err != nil {
		log.Fatal(err)
	}
	DB.AutoMigrate(&domain.User{})

	// dependency injection: repository -> service -> handler
	repo := repository.NewUserRepository(DB)
	svc := service.NewUserService(repo)
	h := handler.NewUserHandler(svc)

	r := gin.Default()
	v1 := r.Group("/api/v1")
	{
		v1.GET("/users/:id", h.GetByID)
	}
	r.Run(":8080")
}
```

<Callout title="Keuntungan" type="info">
Karena service bergantung pada **interface**, kita bisa menguji logika bisnis dengan mock repository tanpa database — persis seperti yang dipelajari di Pertemuan 6.
</Callout>

## Latihan

1. Pindahkan model `User` ke `internal/domain`.
2. Buat `UserRepository` sebagai interface dan implementasi GORM-nya.
3. Buat `UserService` yang memakai repository tersebut.
4. Buat `UserHandler` tipis yang hanya memanggil service.
5. Tulis unit test untuk `UserService` memakai mock repository.

## Checklist

- [ ] Business logic tidak mengimpor Gin atau GORM.
- [ ] Repository mengimplementasikan interface dari domain.
- [ ] Dependency dirakit (wiring) di `main.go`.
- [ ] Service dapat diuji dengan mock.
